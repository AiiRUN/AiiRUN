# Coding Rules

1. Prefer small, scoped changes.
2. Avoid unrelated refactoring during feature work.
3. Use complete file replacements when that is safer for the user.
4. Keep UI, core, and media processing separated.
5. User-visible edits should pass through Commands/Transactions as the architecture matures.
6. Do not silently change established product decisions.
7. Update docs when architecture or UX decisions change.
8. Preserve cross-platform intent.
9. Prefer stable IDs and clear naming.
10. Avoid unnecessary dependencies.
